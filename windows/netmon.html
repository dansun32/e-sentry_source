1. Per-Service Bytes from ETW

netmon-etw.exe opens a private kernel ETW session with the NetworkTCPIP keyword (the source Resource Monitor uses) and sums the payload size of every TCP/UDP send and receive per process.

# Same data, by hand (elevated prompt):
logman start "NT Kernel Logger" -p "Windows Kernel Trace" (net) -o net.etl -ets
logman stop "NT Kernel Logger" -ets

# Leftover session after a crash? Stop it:
logman stop netmon-etw -ets

2. Kernel Events Counted

  • TcpIp/Recv, UdpIp/Recv (+IPv6): inbound bytes per PID.
  • TcpIp/Send, UdpIp/Send (+IPv6): outbound bytes per PID.
  • Process/Stop: clears a PID so a reused PID starts from zero.
  • PID → services via the SCM (EnumServicesStatusEx). Services sharing one svchost.exe appear as one row (Name +N); its bytes belong to the whole process and are not split.

3. TraceEvent Snippet (C#)

using var session = new TraceEventSession("netmon-etw");
session.EnableKernelProvider(
    KernelTraceEventParser.Keywords.NetworkTCPIP |
    KernelTraceEventParser.Keywords.Process);

session.Source.Kernel.TcpIpRecv += d => Add(d.ProcessID, d.size, 0);
session.Source.Kernel.TcpIpSend += d => Add(d.ProcessID, 0, d.size);
session.Source.Process();   // needs Administrator

4. Below the Normal Stack: Npcap, Raw Sockets, WFP

Windows has no public list of raw sockets (GetExtendedTcpTable/UdpTable cover TCP and UDP only), so this panel shows who can see or filter packets below sockets instead: processes that loaded Npcap/WinPcap (wpcap.dll, Packet.dll), optionally processes holding \Device\NPCAP handles (--handles), and the Windows Filtering Platform filters and callouts registered by firewalls and VPN killswitches (such as PIA), grouped by provider, layer and action.
